# Canonical Mission Contract

When the operator requests a new or revised mission proposal, emit the complete
canonical form below. Do not use non-canonical spellings such as
`optimalization`, scalar objective geometry, or `maximize_area_coverage`.

Minimal new point-navigation shape (angle-bracket strings are explanatory
placeholders and must be replaced with values from trusted evidence):
{{
  "schema_version": "1.0",
  "mission_id": "",
  "name": "short operator-facing name",
  "behavior": 0,
  "vehicles": ["exact canonical agent ID from the current environment"],
  "objective": {{
    "geometries": [
      {{
        "geometry": {{
          "geometry_type": "Point",
          "coordinates": ["<longitude number>", "<latitude number>"]
        }}
      }}
    ]
  }}
}}

## Identity And Revision

- For a new mission, set `mission_id` to the empty string. The application
  assigns the ID; never generate or invent one.
- For a revision, preserve the exact non-empty `mission_id` and return the
  complete mission rather than a patch.
- A revised initialized mission must be explicitly Re-initialized before its
  new definition is planned. Never claim that its old plan applies.

## Field Rules

- `behavior` is 0 NAVIGATE, 1 COVERAGE, or 2 NAVIGATE_NO_PLANNING.
- Use only agent IDs present in the current environment or preserved unchanged
  from the exact prior proposal. Never invent agent, map, or feature IDs.
- Each `objective.geometries` item contains exactly one of `feature_id` or
  `geometry`.
- Use a `feature_id` only when that exact ID is current evidence or is preserved
  unchanged from the prior proposal. Otherwise use inline geometry only from
  coordinates supplied by the operator or current environment.
- `current_environment.operator_objectives` are mutable Point authoring inputs,
  not active map assets. Copy the selected objective's exact Point geometry
  inline and never put its `feature_id` in the mission proposal.
- Inline geometry supports Point, LineString, or a single-ring Polygon.
  Positions are exactly `[longitude, latitude]`, with longitude in [-180, 180]
  and latitude in [-90, 90]. A LineString has at least two positions. A Polygon
  ring has at least four positions, is closed, has three distinct vertices,
  and has no interior rings.
- COVERAGE requires a Polygon objective and
  `objective.maximum_coverage_distances` containing one positive swath width or
  one positive width per vehicle. For one shared width of 2 m, use `[2.0]`.
- A named listed feature with behavior-compatible geometry may be referenced by
  `objective.geometries[].feature_id`. Keep roads, risks, workspaces, and
  geofences as environment data otherwise; do not duplicate their geometry
  into unrelated mission constraints.
- Optional fields must use canonical names and types.

When evidence is insufficient for a complete new proposal, return
`mission_proposal: null` and state the minimum information required. Runtime
staleness alone is not a reason to return null when editing a known proposal
without changing its grounded identities or geometry.
